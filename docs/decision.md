# Decisions — git_agent_app

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Flutter/Dart | Matches `voice_notes_app` already in this workspace; reuse its LLM engine code. |
| 2 | Real git clone + commit + push (not GitHub-API-only file edits) | Explicit user requirement — future functionality depends on having the full repo on device, not just single-file API edits. |
| 3 | `git2dart` + `git2dart_binaries` (FFI bindings to real libgit2, prebuilt native libs) for git operations — swapped twice: `dart_git` (spec) → `git_on_dart` (plan-writing) → `git2dart` (during Task 8 implementation) | `dart_git` was abandoned (v0.0.2, 5 years stale, no push support). `git_on_dart` looked active but Task 8's implementer read its actual source and found HTTPS clone/push are non-functional stubs — packfile transfer is explicitly unimplemented, so clone never writes objects and push sends a request GitHub cannot parse. `git2dart` wraps the real libgit2 C library instead of reimplementing the git wire protocol in Dart, and its companion `git2dart_binaries` package supplies prebuilt native libraries so it doesn't reintroduce the manual NDK/CMake complexity that ruled out plain libgit2 bindings at spec time. |
| 4 | GitHub auth via Personal Access Token, pasted in Settings | Simplest to configure (github.com/settings/tokens, `repo` scope); no OAuth app registration/redirect handling needed for v1. |
| 5 | LLM: both cloud API and on-device gguf, switchable now | User wants the toggle in v1, not deferred. |
| 6 | Reuse `voice_notes_app`'s engine abstraction (`AnalysisEngine`/`CloudApiEngine`/`OnDeviceLlamaEngine`/`EngineFactory`) | Already built and working there; port and retarget prompts instead of rebuilding. |
| 7 | `structure.md` bundled in the app, with import (from local storage) and export | User's explicit call — not sourced from inside each cloned repo. |
| 8 | Input file comes from browsing the cloned repo's own file tree | Matches the real workflow (structure something that's already in the repo). |
| 9 | Chat-style iterative refine loop before push | User wants to converse and adjust output, not a single-shot generate. |
| 10 | Save path is user-directed: browse-and-pick folder, or tell the LLM the path in chat | Astro.js-style projects are path-sensitive; app must not guess. |
| 11 | No fake-engine fallback when LLM is unconfigured — block with a settings prompt instead | Pushing placeholder/fake structured content to a real repo is an unacceptable failure mode, unlike voice_notes_app's fake-fallback UX. |
| 12 | v1 excludes skills/sub-agents library, framework switches (LangChain/LangGraph), generic git-actions UI | User explicitly asked to build small first; those are a later spec. |
| 13 | Skills/personas/guardrails design: JSON manifest + plain content files (not markdown frontmatter); one generic `InstructionLibrary` class for both skills and personas; a separate `AgentConfig` model instead of adding fields to `EngineSettings`; strict slash-command grammar (`/skill-slug`, `/persona:slug`, whole-message match only); bundled starter personas shipped as assets | Revised after the user asked for an architect-level second pass rather than accepting the first sketch. Frontmatter parsing is fragile (a stray `---` in content corrupts metadata) — manifest-plus-content-files can't have that failure mode. Skills and personas are structurally identical (name/description/content, add/edit/delete) — one class instantiated twice avoids duplicating the same code and its tests. `EngineSettings` already covers LLM *connection* config; behavior config (persona, guardrails) is a different concern and was kept separate to avoid a growing god object. Loose slash matching risked colliding with normal chat text (e.g. a real file path) or the existing save-path resolver's heuristic — a strict whole-message grammar checked before that logic avoids ambiguity entirely. |
| 14 | On-device model load shows an honest elapsed-time counter, not a percentage | The installed `llama_cpp_dart 0.0.9`'s `ModelParams` hardcodes libgit2's `progress_callback` to `nullptr` — no real progress signal exists in this library version. A fabricated percentage (e.g. estimated from file size) would visibly stall or overshoot and mislead the user; user chose the honest option when presented with the constraint. |
| 15 | Frontend rebuilt to match a user-supplied mockup exactly: black/white visual system, bottom-tab nav (Chat/GitHub/Config), one-time onboarding wizard, GitHub tab as a literal flat state machine (not a restyle of `Navigator.push`) | User explicitly asked for full incorporation of the mockup, then for the GitHub-tab navigation model specifically said "use the design" rather than the lower-risk restyle-only option offered — chose fidelity to the mockup's own code over minimizing the diff. |
| 16 | LangChain/LangGraph toggles included in Config as inert UI (no backend, no persistence) | Approved exception to decision #12 (v1 excludes framework switches) — the mockup shows them, and a visually-present-but-non-functional toggle was judged acceptable since the alternative (omitting them) diverges from the approved design. |
| 17 | On-device engine lifecycle made explicit and shared app-wide (`OnDeviceEngineRegistry`, `isLoaded`/`load()`/`unload()` on `OnDeviceLlamaEngine`) instead of per-screen-instance | User wanted to see whether the on-device model is actually active and control it (load/offload/uninstall) from Config; that only means something if Config and the chat screen observe the same instance, not two independent engines with independent lifecycles. |
| 18 | General Chat becomes real-LLM and repo-aware, but stays tree-only by default — file content read on-demand per file, never preloaded for a whole repo | User's original ask was "feed the LLM the whole repo"; raised as a real cost/context-window risk during brainstorming, and user redirected to structure-and-folders-always + content-on-request instead. GitHub tab's existing structuring chat is reused via a handoff, not duplicated, when the user wants to actually restructure a file found this way. |
